# 目标

## 一句话

把可执行制品恢复成**可证明与它等价、并且可维护**的源码。

不是"复刻一份看起来像的代码"，也不是"能编译就行"。等价性要能被证明，可维护性要能被约束——
两者都有可检验的标准，而不是靠谁说"我看过觉得对"。

## 两个终点

| 终点 | 判据 | 谁来检查 |
| --- | --- | --- |
| **等价** | 下面的分档判据 | 脚本，不依赖人的判断 |
| **可维护** | 人能读懂、能改；`docs/` 只放当前状态 | 人 |

"等价"必须由脚本给出结论。

## 验收分档

不是所有类都值得花同样的代价。分档依据只有一条：

> **这里出错，会不会看起来像是对的？**

| 档 | 什么时候进这一档 | 判据 |
| --- | --- | --- |
| **严格** | 坏了不报错，只是悄悄给出错误结果，且输入空间不可枚举 | 方法级字节码等价 |
| **宽松** | 坏了会大声坏：抛异常、起不来、数据明显不对、没有输出 | ABI 一致 + 冒烟 |
| **划出** | 行为另行定义（许可证的激活语义，密钥将重置） | 只验路由接线存在 |

典型归属：

- **严格**：书源规则引擎（`model.analyzeRule`）、`model.webBook`、`model.rss`、`model.localBook`、
  `help.SourceAnalyzer`、`help.JsExtensions`、`help.http`、编码相关（`BytesEncodingDetect`、
  `EncodingDetect`、`EncoderUtils`、`StringExtensionsKt`、`HtmlFormatter`）
- **宽松**：`data.entities` 的 data class、数据库、配置、TTS、适配器、`verticle`、`utils` 其余
- **划出**：许可证激活行为

分界不看包，看**它是否处在一条会静默出错的数据通路上**。

## 判据

| 判据 | 覆盖 | 不覆盖 |
| --- | --- | --- |
| ABI（`javap -p -s`） | 成员、类型、修饰符、泛型签名、继承关系 | 方法体 |
| 字符串常量逐字比对 | 常量池里的值（正则、模板字符串） | 控制流、分支、参数顺序 |
| 方法级字节码比对 | 指令序列、调用目标、分支结构 | 需归一化；且对源码写法敏感，只能当差异呈现器用 |
| 行为差分 | 端到端语义 | 没探到的路径 |

前两个是自动闸门，**每一片必跑**；第三项是差异呈现器，供人工分类；行为差分是动态兜底。

### 严格档的判据已按实测调整为审查式

原定"方法级字节码零差异"。实测后改判：

> **ABI 一致 + 字符串常量逐字一致 + 逐条审查字节码差异**，
> 每条差异必须被判为「编译噪声」或「语义差异」并留下记录。

理由（都是实测得到的，不是推测）：

- `Intrinsics.checkNotNullExpressionValue(obj, "…")` 的第二个参数是从源码表达式**字面文本**
  生成的。换一种语义等价的写法，常量就变了。
- 平台类型是否被插入空值断言，取决于那个表达式恰好怎么写。
- 局部变量槽位的分配顺序与数量，随源码怎么拆变量而变化。

这三点都不影响语义，但都会改变字节码。所以"机械零差异"实际要求**复原原始源码的写法**，
而不只是复原语义——而原写法在多数情况下不可知，成本无上界。

同时，继续往比对里加归一化会把工具削弱到看不出真问题（已经加了三条：常量池索引、
`checkNotNullExpressionValue` 惯用法、同槽位 `astore/aload` 往返）。所以停在"审查式"。

判据的可信度靠三件事维持：**ABI 闸门自动跑**、**每条差异必须分类**、**分类结论写进
[BATCHES.md](BATCHES.md)**。不分类就等同于没看。

### 字节码比对工具定位

`scripts/verify-bytecode.ps1` 是**差异呈现器**，不是门禁：

- 它给出"哪些方法有差异"，不给出"这个类对不对"
- 它的输出必须逐条分类，分类结果写进批次记录
- 差异多寡与来源语言无关，只与源码写法是否被复原有关

> 早期曾按"来源语言"分档（Kotlin 追零差异、Java 降级）。实测后废弃：差异与来源语言无关。

### 实测数据（2026-11，198 个已编译类）

| 结果 | 类数 |
| --- | --- |
| 字节码一致 | 137 |
| 存在方法差异 | 61 |
| 无法比对 | 0 |

差异分布：第 1 批 Java 来源 48 个（`me.ag2s.epublib` 24、`io.legado.app.lib.icu4j` 15、
`org.kxml2` 6、`me.ag2s.umdlib` 3），utils 里 13 个（Kotlin 与 Java 都有）。

**早期的一个结论被推翻**：曾以为"从源码层重建 Kotlin 能压到零差异、转写 Java 不能"。
实测不是这样——差异与来源语言无关，只与**源码写法**是否被复原有关：

- `Base64`（392 行 Java，直接沿用 CFR 产物）字节码完全一致
- `TextUtils`（Java，严格档）完全一致
- `MD5Utils`（Kotlin，我重写的）只差局部变量分配与两条诊断消息
- `GsonExtensionsKt`（Kotlin）差 5 个方法

所以判据不能按"来源语言"分档，只能按**逐条差异的性质**判。

逐类逐方法清单用 `./scripts/verify-bytecode.ps1 -Artifact <制品>` 可随时重新得到。

## 三个阶段

顺序不能换。

1. **严格还原** —— 目标：与制品等价。
   闸门：静态判据全过。
2. **建行为差分** —— 目标：让第三阶段的改动有判据。
   闸门：覆盖所有只读路由 + 规则引擎的代表性输入。
3. **结构重构** —— 目标：让人能改。
   闸门：行为差分通过。

第 1 步不做，第 3 步无从判断对错；第 2 步不做，第 3 步没有判据。

## 书写纪律

第一阶段就应拿到的可读性（免费，不影响字节码）：

- 局部变量名、参数名取自制品——**制品保留了原始名**，用 `javap -l` 取
- 每个类一行说明它做什么
- 注释与格式

第一阶段**不能做**的（会破坏等价）：

- 抽方法、合并分支、换数据结构
- 改写 `runCatching {}` / `try-catch` 的形态
- 删掉"看起来没用"的 `bl = false;`——那是内联函数留下的标记

## 降级规则

少数类可能达不到零差异（`BookController` 11,622 行、`YueduApi` 7,884 行这类协程密集文件）。
达不到时降级为"ABI 一致 + 行为差分通过"，并在索引里标出。

**不允许因为个别类把整个项目卡住。** 这与"不加区分地花严格预算"是同一类错误的两个方向。

## 索引

每个类一行：`类名 | 档位 | 状态 | 判据结果`。

两个用途：

- 让"完成到哪"不依赖任何人的口报
- 让第三阶段不必把代码读第二遍

索引由脚本从制品与本仓库的类集合差集生成，不手工维护。

## 明确不做

- 重建原始 Gradle 文件——它们不在制品里。本仓库的构建依据制品的依赖集合写成，并如实标注
- 制品字节码或资源触及范围之外的行为
- 为了"统一风格"批量重构
- 把历史堆进 `docs/`——历史属于 git log 与提交信息
